=== Scaling study: work per query at recall@10 >= 0.95 ===
        N  ef used  recall  HNSW dists  flat dists  HNSW ms  flat ms
    1,000       20   0.972         345       1,000    0.270    0.126

   25,000      150   0.976       1,315      25,000    1.601    3.087

Reading:
* At equal accuracy (recall@10 >= 0.95), N grew 25x but HNSW's work per query grew only 3.8x
  (345 -> 1,315 distances). Flat search grew 25x. That is the sub-linear, ~log N behaviour.
* At N = 25,000: HNSW ef = 150 answers in 1.66 ms with recall@10 = 0.970, after looking at 5.4% of
  the archive; flat search takes 3.28 ms (2.0x slower). Small ef (10-50) is sub-millisecond but misses neighbours.
* Honest caveat: flat search is ONE NumPy/BLAS matrix product, HNSW hops in a Python loop. The
  gap widens with N (flat is linear, HNSW is not); C++ libraries (hnswlib, FAISS) run the same
  algorithm far faster than this file (sub-millisecond at much higher recall).
* ef is the speed/accuracy dial: raise it until recall is good enough, then stop.
* Data note: synthetic topic-clustered 768-d vectors (embedding-like). Real sentence embeddings
  are usually easier for HNSW (lower intrinsic dimension), so recall here is a cautious estimate.
